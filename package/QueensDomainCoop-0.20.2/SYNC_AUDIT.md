# Synchronization audit (0.16.0)

What happens in a co-op session, event by event: who starts it, who checks it, whose word counts, which message
carries it, what changes, who is told, and what is kept on disk. Written from the code of 0.15.0 and checked against
the live tests named in the last column (`tests/live/*.py`; `TESTING.md` has their results). Rows marked 0.15.0 are
new or changed in 0.15.0, rows marked 0.16.0 in 0.16.0.

## How a session is built

- **One host, up to three joined players.** Every message goes through the host (a star): a joined player talks to
  the host only. Transport: UDP on a LAN or by address, Steam's peer-to-peer messages between Steam friends.
- **Every game runs the whole game.** There is no dedicated server and the game has no network code of its own: each
  player's copy simulates its own world. The mod makes the copies agree by deciding, for each kind of event, whose
  copy is the truth, and telling the others.
- **Reliable messages** are numbered per link, acknowledged, sent again until acknowledged, and handed on in order,
  once. **Unreliable messages** (positions, 30 times a second) may be lost or arrive late; each carries the sender's
  clock, and a late one never puts back an older state (0.14.0: this now holds for a teammate's health too).
- **Handshake.** Joining compares mod version, message protocol (8 in 0.15.0), game data and features. 0.14.x and
  0.15.0 refuse each other by name.
- **A stalled connection** counts as gone after 20 seconds without a packet (0.15.0; 12 before). A joined player who
  lost the host tries to reach it for 45 seconds. The players' ping times in the roster are kept current (0.15.0:
  they were only sent when someone joined or left).
- **Ids.** Things are named the same in every copy without a shared counter: an enemy by its spawner's save GUID
  (an extra enemy: that name with `+1`), a pickup by its save GUID, an enemy's drop by `D:<enemy>`, an NPC by its
  path in the level, a checkpoint by its location data, a player by a random 64-bit install id. Host decisions that
  must not be repeated carry a number: grants (session epoch, number), rewards (number in the campaign's ledger),
  party rests, journeys, conversations, wipes.

## What is still each player's own

Level, experience, weapons and their levels, coins spent, the shop, the inventory (apart from the grants above), the
journal, and the save file itself: each player keeps their own co-op character. The host's campaign file holds what
belongs to the party: who played, the checkpoint, the difficulty and rules, and the ledger of rewards.

## What was not changed, and known gaps

- A joined player far from every other player in an area the host has not loaded plays that area with their own
  enemies (the host can not run what it has not loaded). Travelling together keeps the party in one place for the
  game's own teleports; walking apart across the map is still possible. 0.16.0 removed the case that made this
  happen to players standing TOGETHER (a player the mod had moved stood next to the host while their game showed
  another part of the map); two joined players in the same far part, without the host, still each run their own.
- Things a level script does on its own in one copy (a scripted event without a savable actor behind it) are not
  sent; the level's triggers count any player's body as the player, which starts them in every copy.
- An enemy a joined copy makes from the host's word (0.15.0) is driven by the host; its own lying in wait does not
  start for that player's look (the host's enemy wakes as the host's game decides).
- Not live-tested: see *Known limitations* in `README.md` and *Not tested / not verified* in `TESTING.md`.
